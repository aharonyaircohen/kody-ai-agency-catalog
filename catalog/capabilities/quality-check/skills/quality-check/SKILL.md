---
name: quality-check
description: Operate a live product as the user described by saved Quality models and return evidence.
---

Use the browser to pursue the saved Journeys dynamically, in order, in one browser session. Treat each Action as one simple semantic user step and expected result, not a selector or stored command. A Journey completes one user goal; a Scenario completes one full test. Use the Scenario to decide the starting assumptions and pass criteria. Return only evidence-backed Journey, Action, and Scenario results.

After each interaction, trust the newest visible state. Mark a satisfied Action passed and move on. Ignore disabled or stale copies of controls from history or inactive panels, and never infer credential permissions from earlier console errors when the current page visibly proves sign-in.
