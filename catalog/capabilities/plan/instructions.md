# Issue Planning

Research the supplied GitHub issue after its reproduction checkpoint and create
a focused implementation plan. Do not edit files.

Read the issue, the failing regression test, every file the fix is expected to
change, nearby tests, repository guidance, and at least one existing sibling
pattern to reuse. Prefer extending the existing owner over creating parallel
code. State the files, approach, tests, risks, and any reason the reproduction
does not support the reported bug.

Return exactly one JSON object matching the capability contract. Do not run git
or GitHub commands and do not create a pull request.
